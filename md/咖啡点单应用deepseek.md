# 咖啡店扫码点单系统（H5先行，小程序后续）需求与设计文档

**版本**：v1.0  
**日期**：2026-08-13  
**状态**：待评审

## 1. 项目概述

### 1.1 背景

一家非连锁精品咖啡店，个体户经营，桌位少于20张，高峰时段约50单/小时。目前无自有扫码点单系统，顾客点单依赖人工。店主已有微信小程序认证资质（可能需续期）、一台初级云服务器、域名备案准备中。计划先开发**H5点单应用**快速上线，待小程序认证和域名备案完成后，再发布微信小程序，实现同一套后端和业务逻辑的无缝迁移。

### 1.2 目标

- 顾客通过扫码（H5链接或后续小程序码）自助点单，支持堂食桌号绑定和外带。
- 店员通过商家端（H5或后续小程序）管理订单、菜单、桌台和查看营业数据。
- 实现订单状态实时更新，出餐时向顾客推送取餐通知（H5阶段使用浏览器通知或页面刷新，小程序阶段使用微信订阅消息）。
- 支持退款申请与店员审核。
- 系统轻量、稳定、易维护，开发成本和后期运维成本可控。

### 1.3 范围

- 本期：用户端点单、支付（H5阶段先模拟支付，小程序阶段接入微信支付）、订单管理、桌台管理、菜单管理、基础统计、退款流程。
- 不包含：会员体系、积分、优惠券、外卖平台对接、复杂库存管理、排队叫号等。

## 2. 产品定位与用户画像

### 2.1 产品定位

精品咖啡店的轻量扫码点单工具，强调简洁、高效、低打扰，符合精品咖啡的品牌调性。

### 2.2 用户画像

- **顾客**：到店消费，年龄20-40岁，习惯移动端操作，注重体验，对咖啡品质有要求。
- **店员/店主**：非技术背景，需要操作简单直观，能快速接单、出餐、处理退款。

## 3. 功能需求详述

### 3.1 用户端（顾客使用）

#### 3.1.1 扫码进入与桌位绑定

- 顾客扫描桌上二维码，进入H5页面（后续为小程序），URL中携带`table_id`参数。
- 页面顶部显示“当前桌号：xx”或“外带模式”。
- 可手动切换桌号或选择“外带/不选座”。
- 若扫描的是吧台“外带码”，则默认外带模式，不绑定桌号。

#### 3.1.2 菜单浏览与加购

- 首页展示商品分类（如：经典咖啡、特调、茶饮、甜点等），采用顶部横向滚动分类栏，下方展示对应商品列表。
- 商品卡片展示：图片、名称、价格、简短描述。
- 点击商品进入详情页，可选择规格（杯型、温度、糖度等），支持备注输入。
- 支持加入购物车，购物车实时显示商品数量和总金额。
- 购物车条常驻底部，点击可展开查看明细，支持增减数量、删除商品。

#### 3.1.3 下单与支付

- 从购物车点击“去结算”，进入订单确认页。
- 确认页显示：桌号/外带、商品明细、备注、合计金额。
- 提交订单后，H5阶段调用模拟支付接口（直接标记为已支付），小程序阶段调用微信支付。
- 支付成功跳转至订单详情页，显示取餐号和状态“制作中”。
- 同时引导顾客订阅取餐通知（H5阶段通过浏览器Notification或提示刷新；小程序阶段使用微信订阅消息）。

#### 3.1.4 订单状态与取餐通知

- 订单详情页实时展示状态：待接单 → 制作中 → 请取餐 → 已完成。
- 当店员在商家端点击“出餐”后，顾客端：
  - 小程序：若已订阅，收到微信服务通知，点击可进入小程序查看。
  - H5：页面定时轮询或使用WebSocket推送，状态更新为“请取餐”，并弹窗提示。
- 订单列表（我的订单）可查看历史订单，支持再来一单。

#### 3.1.5 退款申请

- 订单详情页提供“申请退款”按钮，顾客选择原因并提交。
- 退款申请进入商家端审核列表。
- 顾客可查看退款状态：审核中、已同意、已拒绝。

### 3.2 商家端（店员/店主使用）

#### 3.2.1 登录与权限

- 管理员账号密码登录，使用JWT保持会话。
- 仅授权店员可访问。

#### 3.2.2 首页看板

- 显示今日实时营收、订单总数、待接单数量。
- 新订单提醒：商家端页面自动刷新并播放提示音。

#### 3.2.3 订单管理

- 订单列表按状态Tab分类：待接单、制作中、待取餐、已完成、退款中。
- 每个订单展示：桌号/外带、商品摘要、总金额、下单时间。
- 操作：
  - **接单**：将状态从“待接单”改为“制作中”。
  - **出餐**：状态改为“请取餐”，同时触发顾客端取餐通知。
  - **退款审核**：在“退款中”列表查看详情，可同意或拒绝，同意后调用退款接口（模拟阶段直接改状态）。
- 订单详情可查看完整商品和备注。

#### 3.2.4 菜单管理

- 商品分类管理：增删改分类。
- 商品管理：上下架、编辑名称、图片、价格、规格选项、描述、售罄状态。
- 规格设置：如杯型、温度、糖度等，支持预设选项。

#### 3.2.5 桌台管理

- 桌号列表（如01-20），可增删改。
- 每个桌号生成二维码图片，可批量下载打印。
- 同时生成通用“外带码”。

#### 3.2.6 数据统计

- 按日、周、月查看营收总额、订单总量。
- 热销商品排行。
- 订单时段分布（可选）。
- 以简单图表展示（柱状图、折线图）。

#### 3.2.7 系统设置

- 营业状态：开启/关闭接单。
- 退款设置：是否允许顾客发起退款申请。
- 打印机绑定（可选，支持飞鹅/易联云云打印机）。

## 4. 非功能需求

- **性能**：高峰50单/小时，系统响应时间<1s，支持并发下单。
- **安全**：接口使用HTTPS，商家端需JWT鉴权，用户端无需登录。
- **兼容性**：H5适配主流手机浏览器（微信内置浏览器、Safari、Chrome）；小程序后续兼容微信最新基础库。
- **可维护性**：代码结构清晰，前后端分离，数据库定期备份。
- **扩展性**：预留后续对接微信支付、小程序订阅消息的能力。

## 5. 技术架构与选型

### 5.1 总体架构

- **前端**：使用 `uni-app`（Vue3）开发，一套代码同时编译为H5和微信小程序。
- **后端**：Node.js + Express，提供RESTful API。
- **数据库**：MySQL 8.0。
- **部署**：云服务器（已有），Nginx反向代理，PM2管理Node进程，HTTPS证书（域名备案完成后配置）。
- **文件存储**：商品图片可暂时存服务器本地，未来可迁移至云存储。

### 5.2 关键依赖

- 后端：`express`, `mysql2`, `cors`, `jsonwebtoken`, `bcryptjs`, `dotenv`, `qrcode`（生成桌码）。
- 前端：`uni-app`, `pinia`（状态管理）, `axios`（请求封装）。

### 5.3 支付方案

- H5阶段：模拟支付，订单创建后直接标记为`paid`，后续替换为微信支付。
- 小程序阶段：接入微信支付，使用已开通的商户号。

### 5.4 取餐通知

- H5阶段：前端轮询订单状态（每10秒）或使用WebSocket，状态变更时弹窗提醒。
- 小程序阶段：使用微信订阅消息，后端调用API推送。

## 8. API接口设计概要

### 8.1 用户端接口（无需登录）

- `GET /api/categories`：获取分类及商品列表。
- `GET /api/products/:id`：获取商品详情。
- `GET /api/tables`：获取桌台列表（用于手动选择）。
- `POST /api/orders`：创建订单，参数：`table_id`或`order_type=takeaway`，`items`数组，`remark`。返回订单ID、取餐号。
- `POST /api/orders/:id/mock-pay`：模拟支付，标记订单为已支付。
- `GET /api/orders/:id`：查询订单状态（含轮询）。
- `POST /api/orders/:id/refund`：申请退款。
- `GET /api/orders/:id/refund-status`：查询退款状态。

### 8.2 商家端接口（需JWT）

- `POST /api/admin/login`：登录。
- `GET /api/admin/orders?status=&page=&date=`：订单列表。
- `PUT /api/admin/orders/:id/status`：更新订单状态（接单、出餐、完成）。
- `GET /api/admin/orders/:id`：订单详情。
- `GET /api/admin/refunds`：退款申请列表。
- `PUT /api/admin/refunds/:id`：审核退款。
- `GET /api/admin/stats/today`：今日营收、订单数。
- `GET /api/admin/stats/products`：热销排行。
- `GET /api/admin/categories` / `POST` / `PUT` / `DELETE`：分类管理。
- `GET /api/admin/products` / `POST` / `PUT` / `DELETE`：商品管理。
- `GET /api/admin/tables` / `POST` / `PUT` / `DELETE`：桌台管理。
- `GET /api/admin/tables/:id/qrcode`：生成桌台二维码。

### 8.3 通用约定

- 返回格式：`{ "code": 0, "data": {}, "msg": "success" }`
- 错误码：0成功，1参数错误，401未授权，500服务器错误。

## 11. 风险与注意事项

- **域名备案未完成**：H5部署需使用IP+端口或临时域名，但HTTPS可能受限。建议尽快完成备案，或先用IP访问测试。
- **支付方案**：H5模拟支付仅用于测试，正式营业需切换到小程序支付或微信H5支付（需额外申请）。
- **取餐通知**：H5阶段无法像小程序那样推送服务通知，需依赖页面刷新或主动轮询，体验略差。可引导顾客保留页面。
- **数据安全**：订单数据需定期备份，商户密码需加密存储。
- **二维码打印**：生成二维码后需测试扫描，确保桌号参数正确。
