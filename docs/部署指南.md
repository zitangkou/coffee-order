# Coffee OS 云服务器部署指南

> 适用环境：腾讯云 Ubuntu 22.04 LTS，4核4G  
> 部署方式：Docker（MySQL 8 + 后端 API + 前端 Nginx 三个容器）  
> 更新时间：2026-08-26

---

## 0. 部署架构

```
微信小程序 / 商家内部浏览器
      │
      ▼
   宿主机 HTTPS 网关 → Nginx 容器（内网端口）
      │
      ├── /          → 商家内部 Web 后台
      ├── /api/      → 反代到后端容器 :3000
      └── /uploads/  → 反代到后端容器（桌码图片等）
              │
              ▼
        后端 API 容器（Node.js + Prisma）
              │
              ▼
        MySQL 8 容器（数据持久化）
```

## 2. 获取代码

两种方式任选：

### 方式 A：git clone（推荐，方便后续更新）

先把项目推到 GitHub / Gitee / 腾讯工蜂，然后在服务器上：

```bash
apt update && apt install -y git
git clone git@github.com:zitangkou/coffee-order.git
cd coffee-order
```

### 方式 B：本机打包上传

本机（Mac）执行：

```bash
cd ~/Projects
tar czf coffee-order.tar.gz --exclude=node_modules --exclude=dist --exclude=.git coffee-order
scp coffee-order.tar.gz root@<服务器公网IP>:~/
```

服务器上解压：

```bash
apt update && apt install -y tar
tar xzf coffee-order.tar.gz
cd coffee-order
```

## 3. 配置部署参数

```bash
cd coffee-order
cp deploy/.env.example .env
nano .env   # 用 vim 也行
```

必改项：

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `HTTP_PORT` | 对外访问端口 | `80` |
| `WEB_BASE_URL` | 对外访问地址（生成桌码用） | `https://nagacoffee.site` |
| `MYSQL_PASSWORD` | MySQL 密码，至少 24 位 URL 安全字符 | 随机强密码 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码，至少 24 位 URL 安全字符 | 随机强密码 |
| `JWT_SECRET` | 登录令牌密钥，至少 32 位 | 随机长字符串 |
| `VITE_MP_API_BASE` | 小程序请求 API 的 HTTPS 地址 | `https://nagacoffee.site/api` |
| `VITE_ASSET_BASE` | 小程序图片等静态资源地址 | `https://nagacoffee.site` |

保持默认即可的项：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE` | `/api` | 前端同源调 API，一般不用改 |
| `MOCK_PAYMENT` | `false` | 生产必须关闭模拟支付 |
| `PRINTER_ENABLED` | `false` | 云打印机接入后改 `true` |

首次部署还需设置 `INITIALIZE_SEED=true`，部署成功后立即改回 `false`。如果服务器已有旧版 `prisma db push` 创建的业务库，首次切换版本化迁移时改设 `BASELINE_EXISTING_DB=true`，成功后立即改回 `false`；执行前必须先备份。

部署脚本会在构建前检查密码强度，缺失或仍使用弱值会直接拒绝启动。微信证书挂载后需确保容器内 UID 1000 的 API 用户具有只读权限；不要放宽为全员可写。

## 4. 一键部署

```bash
./deploy.sh
```

脚本会自动完成：

1. 安装 Docker 与 Docker Compose（如果没装）
2. 配置腾讯云镜像加速（`mirror.ccs.tencentyun.com`）
3. 构建并启动 MySQL、非 root API、非 root Web，以及一次性上传目录权限初始化容器
4. 应用已提交的 Prisma 版本化迁移；仅显式开启时写入初始数据
5. 健康检查 + API 验证

看到以下输出即成功：

```
{"code":0,"data":{"ok":true},"msg":"success"}
部署完成！
```

> 首次构建需要拉取基础镜像，约 3–8 分钟，取决于网络。

> 禁止在生产环境执行 `prisma db push --accept-data-loss`。后续表结构变更必须生成并提交 migration，再由 `prisma migrate deploy` 应用。

## 5. 手动安装 Docker（备选）

如果不想用脚本自动装，也可以手动装完再执行 `./deploy.sh`：

```bash
# 1. 官方脚本安装 Docker
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 2. 安装 Docker Compose v2
apt-get install -y docker-compose-plugin
# 或手动安装：
# mkdir -p /usr/local/lib/docker/cli-plugins
# curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
#   -o /usr/local/lib/docker/cli-plugins/docker-compose
# chmod +x /usr/local/lib/docker/cli-plugins/docker-compose

# 3. 配置腾讯云镜像加速
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
EOF
systemctl restart docker

# 4. 验证
docker version
docker compose version
```

然后回到部署流程：`cp deploy/.env.example .env` → `./deploy.sh`。

## 8. 域名 + HTTPS（备案完成后）

### 8.1 域名解析

在腾讯云 DNSPod 把域名 A 记录指向服务器公网 IP。

### 8.2 配置 HTTPS

```bash
# 安装 certbot
apt install -y certbot python3-certbot-nginx

# 申请证书并自动配置 Nginx（nginx 在容器里，需先改端口方案，见下方说明）
certbot --nginx -d nagacoffee.site
```

> 本项目 Nginx 运行在容器内。配置 HTTPS 有两种方式：
>
> 1. 简单方式：在宿主机再装一个 Nginx 做 443 终结，反代到容器的 80 端口；
> 2. 或把证书文件挂载进 web 容器并改 `deploy/nginx.docker.conf` 增加 443 server 块（需要时我可以帮你改）。

### 8.3 更新 `.env`

确认 `WEB_BASE_URL=https://nagacoffee.site`，重新生成桌码。

## 9. 安全加固（上线前必做）

```bash
# 1. 修改商家后台默认密码（登录后台操作）或改种子数据后重建

# 2. 修改 SSH 端口并禁止 root 密码登录（建议改用密钥）
#    腾讯云控制台生成密钥对，或：
ssh-keygen   # 本机生成公钥
ssh-copy-id root@<服务器IP>
sed -i 's/^#Port 22/Port 2222/' /etc/ssh/sshd_config
sed -i 's/^#PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart sshd

# 3. 开启 UFW 防火墙（只放行必要端口）
ufw allow 22
ufw allow 80
ufw allow 443
ufw enable

# 4. 数据库与上传图片自动备份（推荐用仓库自带脚本）
bash deploy/install-backup.sh   # 安装每日 03:00 自动备份
# 手动备份一次：
bash deploy/backup.sh
# 备份位置：/opt/backups（保留 14 天，可改 BACKUP_DIR / BACKUP_RETENTION_DAYS）

# 验证最新备份确实可恢复：只使用临时库，不覆盖生产库
bash deploy/restore-verify.sh

# 容器、端口、非 root、UFW、HTTPS 只读检查（不会输出任何密钥值）
bash deploy/security-check.sh

# 每 5 分钟检查容器、数据库就绪、HTTPS、磁盘和备份新鲜度
bash deploy/install-monitor.sh

# 微信登录/支付/回调/订阅配置就绪检查：只输出 ready/not-ready
bash deploy/wechat-readiness.sh
```

安装脚本会配置每日数据库/上传文件备份及每周自动恢复验证。监控脚本失败时以非零状态退出，请在腾讯云监控或日志服务中为 `/var/log/coffee-monitor.log` 的“未通过”配置告警。备份仍需同步到腾讯云 COS 等异机存储；仅保存在同一块 40G 系统盘不能视为完整灾备。

> 说明：正式接入微信支付前，在 `.env` 配置 `WECHAT_API_V3_KEY` 与 `WECHAT_PLATFORM_CERT_PATH`（证书文件挂载进 server 容器），回调验签自动启用；未配置时支付回调一律拒绝（fail-closed）。

支付成功回调为 `https://nagacoffee.site/api/payment/callback`，退款结果回调为 `https://nagacoffee.site/api/refund/callback`。退款审核通过只代表已向微信提交申请，订单必须在退款回调或主动查询确认成功后才进入 `REFUNDED`。

完整提审顺序见 [小程序发布执行清单.md](小程序发布执行清单.md)。

## 11. 常见问题

### 拉取镜像很慢 / 超时

```bash
# 确认镜像加速已配置
cat /etc/docker/daemon.json
# 换源后重启 docker 再试
systemctl restart docker
docker compose up -d --build
```

### 80 端口被占用

```bash
ss -lntp | grep :80
# 如果被其他程序占用，改用其他端口：.env 里 HTTP_PORT=8080 后重新部署
```

### 后端健康检查失败 / API 报 502

```bash
docker compose logs server   # 看后端报错
docker compose logs mysql    # 看数据库是否正常
docker compose ps            # 确认 mysql 是否 healthy
```

常见原因：MySQL 首次初始化慢，等 1–2 分钟重启 server：`docker compose restart server`。

### 桌码扫出来打不开

确认 `.env` 的 `WEB_BASE_URL` 是公网可访问的地址，且安全组放行了对应端口；改完后重新生成桌码。

### 想重置数据（谨慎）

```bash
docker compose down -v        # 删除数据卷
docker compose up -d --build  # 重新建表 + 种子数据
```
