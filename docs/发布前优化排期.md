## 第 1 批完成标准

- 管理员被禁用、改角色或重置密码后，旧 JWT 立即失效。
- 首次登录或密码重置后，服务端只允许访问改密接口；改密成功换发新令牌。
- 审计日志不记录密码摘要。
- 生产环境禁止 console 短信和游客登录；短信未接供应商时明确关闭手机号绑定。
- 验证码使用安全随机数和 HMAC 摘要保存，单条验证码连续错误达到上限后失效。
- 新增自动化回归覆盖令牌版本、强制改密、管理员禁用、生产游客和短信开关。

## 每批统一交付要求

1. SQLite 开发 schema 与 MySQL 生产 migration 同步。
2. 前后端类型检查、相关状态机测试、生产发布门禁通过。
3. 不提交本地数据库、构建产物和任何私密发布资料。
4. 更新 `PROJECT_STATUS.md` 与发布清单后提交；经确认后推送 `origin/main`。

详细风险和验收依据见 `docs/发布前全面复盘-2026-08-29.md`。

## 第 2 批完成标准

- 取餐码按 `Asia/Shanghai` 营业日使用数据库原子递增序列生成，不再受 900 个随机候选限制。
- 新订单保存唯一取餐键；历史订单无需回填，不会因历史重复数据阻断 migration。
- 顾客端每次结算生成一个客户端幂等键，网络重试复用该键；提交按钮在请求期间锁定。
- 服务端按“用户 + 客户端幂等键”返回同一订单，单进程并发使用 single-flight，跨实例依靠数据库唯一约束。
- 自动化回归覆盖并发同键、顺序重试、不同订单取餐码唯一和北京时间跨日。

## 第 3 批完成标准

- 待支付订单详情页支持继续拉起微信支付和主动取消；取消前先向微信关单，若查明已支付则拒绝取消。
- 支付成功结果同时校验 AppID、商户号、CNY 币种、订单号、交易号和分单位金额。
- `Payment.orderId` 增加数据库唯一约束；相同交易号重复通知保持幂等，不同交易号不能写入同一订单。
- 真实微信支付首次确认成功后调用统一出单入口；打印异常不回滚支付，日志只记录订单号，不输出完整订单对象。
- 自动化回归覆盖错误归属/币种/金额拒绝、重复通知、第二交易号拒绝、越权取消和正常取消。

真机统一下单、回调、主动查单、关单和实际打印机仍需在支付开通及设备型号确定后验收。
