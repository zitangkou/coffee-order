# Coffee OS 微信小程序发布执行清单

> 更新：2026-08-29。首发范围为顾客微信小程序 + 商家内部 Web 后台，顾客 H5 暂缓。
> 安全约束：不在 Git、文档、终端输出或会话中记录 AppSecret、APIv3 密钥、私钥、证书内容及真实支付配置值。

## 一、当前状态

- [x] 小程序顾客端已排除游客登录、商家后台页面和后台 API。
- [x] 正式构建固定使用 `https://nagacoffee.site/api`，图片使用 `https://nagacoffee.site`。
- [x] 支付回调、主动查单、超时关单、退款申请、退款回调、主动同步及幂等状态机已具备代码闭环。
- [x] 退款成功为不可逆终态；乱序回调、重复回调和并发退款申请已有自动化回归。
- [x] 生产数据库使用 `prisma migrate deploy`，禁止启动时 `db push --accept-data-loss`。
- [x] 数据库备份、校验、临时库恢复演练、容器安全检查和微信布尔就绪检查已提供脚本。
- [x] Docker 构建上下文排除根环境文件、私密目录及常见私钥/证书格式；发布门禁不输出私密配置值。
- [ ] 公网 443、TLS 证书和宿主机 Nginx 尚需在服务器实装验证。
- [ ] 小程序认证、隐私保护指引、真实登录/支付/退款/订阅消息仍需后台与真机联调。

## 二、服务器上线准备

1. 先做备份及恢复验证：

   ```bash
   bash deploy/backup.sh
   bash deploy/restore-verify.sh
   ```

2. 安装 `deploy/nginx.conf` 对应的 `nagacoffee.site` HTTPS 网关，确认腾讯云安全组和 UFW 仅开放必要端口；MySQL、API、容器 Web 端口不得直接暴露公网。
3. 旧版已建表数据库首次切换 migration 前，备份后仅执行一次基线流程；全新数据库只在首次部署显式初始化 seed。
4. 部署后执行：

   ```bash
   bash deploy/security-check.sh
   bash deploy/wechat-readiness.sh
   ```

   两个脚本只输出检查状态，不显示配置值。
5. 将每日备份同步到腾讯云 COS 等异机存储，并保留至少一次真实恢复演练记录。

## 三、微信公众平台配置

- [ ] 服务器域名：request/downloadFile 使用 `https://nagacoffee.site`；若顾客端增加上传，再配置 uploadFile。
- [ ] 业务域名、ICP备案、HTTPS 证书链和 TLS 版本符合平台要求。
- [ ] 隐私保护指引与小程序内隐私政策保持一致，补齐经营主体、客服联系渠道、实际保存期限。
- [ ] 配置出餐订阅消息模板，前后端使用同一模板；模板值只通过私密环境注入。
- [ ] 体验版成员、类目、服务内容、头像、名称、简介及版本说明准备完成。

## 四、微信支付联调

- [ ] 微信登录可稳定获得 openid，旧令牌、注销账号和跨用户访问继续被拒绝。
- [ ] JSAPI 下单、取消支付、支付成功回调、回调延迟、重复回调、主动查单均通过。
- [ ] 超时未支付订单先微信关单，再更新本地取消状态；遇到已支付不得取消。
- [ ] 管理员同意退款后只进入“处理中”，必须由微信退款结果或主动查询确认后才能成为“退款成功”。
- [ ] 验证退款成功、处理中、关闭、异常、重复回调和同一退款单号重试。
- [ ] 核对支付金额、退款金额、商户订单号、微信交易号和退款单号；完成至少一次日终人工对账。

微信官方流程参考：[关闭订单](https://pay.wechatpay.cn/doc/v3/merchant/4012791839)、[申请退款](https://pay.wechatpay.cn/doc/v3/merchant/4013071036)、[退款结果回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791906)。

## 五、构建与真机验收

1. 普通正式构建门禁：

   ```bash
   PRODUCTION_RELEASE=true ./scripts/release-check.sh
   ```

2. 最终提审构建需在私密构建环境中注入订阅模板并启用更严格门禁：

   ```bash
   FINAL_SUBMISSION=true PRODUCTION_RELEASE=true ./scripts/release-check.sh
   ```

   门禁只判断配置是否存在且产物是否合规，不打印注入值。
3. 真机覆盖：首次进入、扫码桌号、外带码、冷启动、弱网、断网恢复、重复点击、停业、售罄、规格变更、支付取消、支付结果未知、退款和订阅通知。
4. 检查不同尺寸、刘海/灵动岛、安全区、字体放大、前后台切换及微信最低基础库兼容性。

当前无需私密资料即可执行的发布门禁已通过。正式提审门禁会继续等待有效 AppID 与私密订阅模板注入，不应通过修改代码绕过。

## 六、提审与发布

- [ ] 冻结发布 commit，记录数据库 migration、构建时间、体验版版本号和验收人。
- [ ] 提交前确认 `deploy/security-check.sh`、`deploy/wechat-readiness.sh`、正式发布门禁全部通过。
- [ ] 审核期间不变更线上数据库结构和支付配置；若必须变更，重新生成体验版并回归。
- [ ] 审核通过后先灰度营业，观察登录失败率、支付回调、退款、5xx、磁盘和备份情况，再正式放量。
- [ ] 回滚只回滚应用镜像；数据库 migration 不做破坏性回退，使用向前修复 migration。

## 七、仍需人工完成的发布阻断项

1. 服务器 443/TLS/Nginx/UFW 实装与公网验证。
2. 微信后台合法域名、隐私指引、类目和体验版配置。
3. 真实 AppID、登录、支付、退款、订阅模板联调。
4. 经营主体、客服、留存期限、退款规则最终文本确认。
5. 真实商品图、桌贴小程序码、门店员工操作培训与应急联系人。

## 八、接下来的执行顺序（简洁版）

1. **备案/服务器阶段**：部署腾讯云、签发证书、启用 Nginx 443、收紧安全组与 UFW，执行安全检查和首次备份恢复演练。
2. **小程序认证完成**：配置合法域名和隐私指引，私密注入 AppID/Secret，完成登录、扫码场景和体验版真机回归。
3. **支付开通完成**：私密挂载商户证书和支付配置，验证下单、回调、查单、关单、退款、退款回调及人工对账。
4. **提审前**：补齐经营主体文本和订阅模板，运行最终提审门禁，冻结发布 commit，完成全流程 UAT。
5. **发布后**：先小范围营业，重点观察登录、支付回调、退款、5xx、磁盘、备份和告警，再逐步放量。
