# 单机多项目 Docker 部署指南

> 适用：一台腾讯云 4核4G 服务器上同时运行 coffee-order 及其它项目  
> 更新：2026-08-15

---

## 1. 两种方案怎么选

**方案 A：端口隔离（最简单，适合测试阶段 / IP 访问）**

- coffee-order 用 8080，项目 B 用 8081，项目 C 用 8082……
- 优点：不用域名，改个端口就能跑；缺点：端口多难记，HTTPS 证书必须按域名，正式运营不推荐。

**方案 B：域名网关（推荐，正式运营）**

- 宿主机装一个 Nginx 统一监听 80/443，按域名转发到各项目的容器；
- 各项目容器只监听 `127.0.0.1` 的内网端口，不对外暴露；
- 优点：域名即入口，HTTPS 每个项目独立证书，安全组只需放行 22/80/443，端口不再冲突。

```
公网 80/443
     │
宿主机 Nginx（网关：按 server_name 路由 + SSL 终结）
     ├── coffee.example.com → 127.0.0.1:8080 （coffee web 容器）
     ├── b.example.com      → 127.0.0.1:8081 （项目 B web 容器）
     └── c.example.com      → 127.0.0.1:8082

每个项目 = 独立目录 + 独立 compose 项目
  web(nginx) → api(node) → mysql(独立容器/独立库)
```

## 2. 多项目共存的核心原则

1. **目录即项目**：每个项目一个目录，目录名就是 compose 项目名（或在 compose 里显式写 `name: xxx`），彼此网络、数据卷、容器完全隔离。
2. **命名加前缀**：容器名、数据卷、数据库名都带项目前缀，避免冲突（coffee 的 MySQL 卷是 `coffee-order_mysql_data`，另一个项目就是 `project-b_mysql_data`）。
3. **端口互不占用**：方案 A 用不同公网端口；方案 B 各项目 web 容器都映射到 `127.0.0.1:不同端口`。
4. **镜像源配置只做一次**：`/etc/docker/daemon.json` 和 docker 重启属于全局操作，不要在每个项目的部署脚本里重复执行（会短暂中断其它项目的容器）。拆成一次性的 `setup-docker.sh`。
5. **资源限额**：4G 内存建议 MySQL ≤1G、每个应用容器 ≤512M，并配 2G swap；用 `docker stats` 监控。

## 3. 把 coffee-order 改造成网关模式（方案 B）

### 3.1 项目容器改内网端口

coffee-order 已完成此改造：`docker-compose.yml` 顶部有 `name: coffee-order`，web 端口映射为只绑本机：

```yaml
  web:
    ports:
      - "127.0.0.1:8080:80"
```

对应 `.env`：`HTTP_PORT=8080`（只表示本机端口），`WEB_BASE_URL=https://coffee.example.com`。

> MySQL 不需要任何改动：compose 里本来就没把 3306 暴露到宿主机，只在内网网络里供后端访问。

### 3.2 宿主机装网关 Nginx

```bash
apt install -y nginx
```

为每个项目建一个站点配置，例如 `/etc/nginx/sites-available/coffee-order`：

```nginx
server {
    listen 80;
    server_name coffee.example.com;
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用并重载：

```bash
ln -s /etc/nginx/sites-available/coffee-order /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

其它项目照抄，改域名和 8081/8082 端口即可。

### 3.3 HTTPS（备案完成后）

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d coffee.example.com
```

certbot 会自动改写上面的 server 块（加 443 和证书），每个项目各执行一次。

## 4. 新项目的接入模板

任何新项目按这个模板组织即可，与 coffee-order 互不干扰：

仓库已提供可直接复制的模板目录 `deploy/project-template/`（含 compose、.env.example、Nginx 站点配置、示例应用），用法见模板内 README。

```
/opt/project-b/
├── docker-compose.yml     # 顶部写 name: project-b
├── .env                   # 独立端口/库名/密钥
└── ...                    # 项目自己的 Dockerfile/代码
```

```yaml
# /opt/project-b/docker-compose.yml（示意）
name: project-b

services:
  app:
    build: .
    restart: unless-stopped
    ports:
      - "127.0.0.1:8081:80"
    environment:
      DB_HOST: mysql
    depends_on:
      mysql:
        condition: service_healthy
  mysql:
    image: mysql:8.0
    restart: unless-stopped
    environment:
      MYSQL_DATABASE: project_b
      MYSQL_USER: project_b
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
    volumes:
      - project_b_mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]

volumes:
  project_b_mysql_data:
```

部署：

```bash
cd /opt/project-b
cp .env.example .env && nano .env
docker compose up -d --build
```

## 5. 一次性环境初始化脚本

镜像源、Docker 安装这类全局操作只做一次，单独抽出来，避免每次部署都重启 docker。

仓库已提供现成脚本，服务器首次初始化时执行一次：

```bash
cd /opt/coffee-order
bash deploy/setup-docker.sh
```

之后每个项目（包括 coffee-order 自己）只跑 `./deploy.sh`，不再触碰 Docker 全局配置。`setup-docker.sh` 会保留已有 `/etc/docker/daemon.json` 的其它设置，只更新镜像加速项；普通用户首次加入 `docker` 组后需重新登录一次。

coffee-order 的 `deploy.sh` 只在检测不到 Docker/Compose 时调用该初始化脚本；日常更新不会重启 Docker，因此不会中断同机其它项目。

## 6. 内存与运维建议（4核4G）

- 给容器加内存上限，防止单个项目吃满整机：

```yaml
services:
  mysql:
    mem_limit: 1g
  server:
    mem_limit: 512m
  web:
    mem_limit: 256m
```

- 加 2G swap（腾讯云控制台或 `fallocate` + `mkswap`），高峰更稳。
- 日常监控：`docker stats`、`docker ps`、每个项目 `docker compose logs -f`。
- 备份：每个项目独立备份自己的数据卷，建议脚本里按项目前缀命名备份文件。
- 更新节奏：逐项目 `git pull && docker compose up -d --build`，一次只动一个项目，便于回滚。

## 7. 安全组端口清单

方案 B 只需放行：

| 端口 | 用途 |
| --- | --- |
| 22 | SSH |
| 80 | HTTP（网关） |
| 443 | HTTPS（网关） |

各项目容器端口（8080/8081…）只绑 `127.0.0.1`，不需要在安全组放行。
